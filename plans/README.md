# Astraa engineering improvement plans

Generated by the `improve` workflow on 2026-08-08 and expanded after a full
copy, landing, route/interaction, coming-soon, and contributor-documentation
audit on 2026-08-09. The baseline remains commit `94a1b1f` on branch
`astraa-v2`, with Plans 001–007 already implemented in the uncommitted worktree.
Execute the plans in order. Every executor must read its entire plan before
editing, honor its STOP conditions, and update its status here when finished.

The audits were read-only on source code; only this `plans/` handoff set was
written. Together they covered source architecture, every registered/static
rendered route at desktop and mobile, core interactions for all 12 available
tools, copy, landing hierarchy/motion, accessibility, incomplete features,
repository documentation/skills, Notion destination semantics, performance,
and technical SEO. They did not use production Search Console, production
analytics, field Core Web Vitals, or private third-party service calls.

## Audit baseline

- `npm run lint` exited 0 with 9 warnings. The script currently tolerates 50
  warnings (`package.json:9`).
- `npm test` passed 42 files and 330 tests. Tests only include
  `lib/**/*.test.ts` in a Node environment (`vitest.config.ts:5-9`).
- `npx tsc --noEmit` exited 0.
- A production `next build --webpack` at the audited commit completed, but logged
  middleware deprecation and server-side `localStorage` warnings.
- The rendered `/contribute` route showed the app error boundary because its
  `next/image` remote hostname is not configured
  (`components/contribute/contribute-client.tsx:113-119`, `next.config.js:4`).
- The dev console reproduced a theme hydration mismatch on multiple routes and
  `localStorage.getItem is not a function` on persisted editor routes.
- `npm audit --omit=dev` reported 25 advisories: 12 high, 12 moderate, and 1
  low. The lockfile and installed modules also disagreed, so a clean-install
  verification is required.

## Highest-impact findings

1. A browser-shipped CoinGecko demo credential is hardcoded at `lib/api.ts:1`.
   Deleting it from the current file is not enough; it must be revoked or
   rotated because it is already committed.
2. The public OpenRouter Server Action at `lib/openrouter.ts:9-60` has no rate
   limit, request timeout, or spend boundary, and accepts five times the UI's
   intended word limit.
3. Regex matching still runs untrusted patterns synchronously before the worker
   fallback (`components/regex-tester/regex-tester-client.tsx:127-157`). A
   catastrophic pattern can block the main thread before elapsed time is
   checked (`lib/regex-tester/match.ts:24-50`).
4. Zustand persistence selects a `localStorage` adapter during server rendering
   (`lib/stores/storage.ts:85-110`), producing runtime warnings and an unsafe
   server/browser boundary.
5. Fiat and crypto converters refetch on every amount change, do not abort or
   ignore stale requests, and can render an older response over a newer one
   (`components/currency/fiat-converter.tsx:36-89` and
   `components/currency/crypto-converter.tsx:31-68`).
6. Sentry records all traces, enables Replay, enables logs, and sends default
   PII (`instrumentation-client.ts:7-29`), while public copy says no data is
   collected (`components/contribute/contribute-client.tsx:58-60`).
7. The root mounts an unused random activity simulator every three seconds
   (`lib/activity-tracker.tsx:38-142`) and a mutable context around a static tool
   registry (`lib/tools-context.tsx:13-49`). Neither earns its runtime cost.
8. Individual WIP routes are mostly `noindex`, but the WIP gate fails open when
   an environment variable is missing (`components/wip.tsx:8-11`). All seven
   registered games are unavailable (`lib/games.ts:12-64`), yet `/games` is
   indexable and advertised as playable.
9. Global schema and sitemap dates claim a fresh modification every day
   (`app/layout.tsx:110-135`, `app/sitemap.ts:8-67`), and several rendered tool
   pages add the brand twice through nested title templates.
10. CI runs tests and build only (`.github/workflows/ci.yml:20-26`); it does not
    gate lint, TypeScript, dependency advisories, hydration, route crashes, or
    browser behavior.

## Dependency notes

- 001 establishes deterministic rendering and WIP behavior; later browser and
  SEO assertions depend on those routes rendering normally.
- 002 creates the protected server boundaries that 003's rate-fetching hook
  consumes.
- 004 documents and redacts the actual external flows after 002 and 003 settle
  their request shapes.
- 005 removes obsolete providers, stores, stats code, and dependencies only
  after earlier phases have stopped relying on them.
- 006 adds browser-level regression coverage around the simplified runtime.
- 007 uses the final registry and route availability from 005 and the route
  checks from 006 to emit truthful crawl/index signals.
- 008 is first in the follow-up sequence because every later executor should use
  the same architecture, code-quality, and feature workflow instead of copied
  `AGENTS.md`/`CLAUDE.md` rules.
- 009 repairs the verified route and accessibility baseline before copy and
  layout changes could obscure the regressions.
- 010 establishes canonical names and the copy/data-boundary contract consumed
  by public docs, the homepage, and both new launches.
- 011 publishes `/docs` before 012 adds Docs to primary navigation, preventing a
  temporary broken destination.
- 012 uses the final copy and docs IA, and records comparable mobile performance
  before feature launches change catalog counts.
- 013 launches SQL first because it is the strongest focused-utility candidate;
  it also removes hidden prototypes that currently bypass Knip.
- 014 is deliberately last: shipping the first game changes `/games`, sitemap,
  metadata, and catalog semantics together and should happen only after the
  tool/docs/home surfaces are stable.

## Follow-up audit findings (2026-08-09)

1. All 12 available tools completed their tested core workflows without runtime
   errors, but the Hash, Image, Units, Password, Snippet, and Calculator routes
   have confirmed accessible-name/state/live-result gaps.
2. `/games/2048` is registered but uniquely renders the generic 404; every peer
   planned route returns a truthful `200 + noindex` construction page.
3. The mobile Contribute CTA row clips both outer rounded edges at 390 px.
4. The homepage renders only a hydrated, oversized hero. Its first real product
   proof sits at the bottom of the 390×844 viewport, and it sends the primary
   CTA to Explore while navigation also exposes Tools.
5. Homepage mobile baseline is 343.7 KB JavaScript, 876 ms LCP, and 0.0392 CLS;
   the redesign must reduce CLS without increasing initial JavaScript.
6. Product copy includes fabricated-looking JSON users/ratings/dates, absolute
   “100% local” language, ambiguous local “Upload” actions, cryptographic
   superlatives, generic AI/catalog hype, timing promises, and three inconsistent
   canonical tool names.
7. Nine live tools have server-rendered guides; AI Text Generator, Scientific
   Calculator, and Unit Converter do not.
8. SQL's hidden regex formatter can corrupt quoted/comment text and claims
   validation. Memory's hidden game has duplicate pairs and stale reset timers.
   Hidden Music, Dino, and Snake prototypes are not safe launch foundations.
9. `.agents/` and `.claude/` are ignored, agent manuals drift, and no repository
   gate verifies a canonical skill registry.
10. Footer and README label the Notion Roadmap as Docs. The verified Notion
    `/documentation` page is a Tweets/Posts gallery and belongs under Hall of
    Fame; the real technical corpus is `docs/*.md` and needs `/docs` routes.
11. Local Playwright can silently reuse an unrelated application already bound
    to port 3002 because its URL probe is overrideable while its start command
    is hard-coded. Plan 009 now makes server reuse explicit and port-aligned.

## Current research basis

- Next.js treats Server Actions as public HTTP endpoints and recommends the
  same authorization checks as route handlers:
  <https://nextjs.org/docs/app/guides/authentication>.
- Next.js 16 renamed Middleware to Proxy and recommends avoiding it unless a
  request boundary genuinely needs it:
  <https://nextjs.org/docs/app/getting-started/proxy>.
- React documents effect cleanup as the way to prevent stale network responses
  from winning a race:
  <https://react.dev/reference/react/useEffect>.
- Next.js caching must match the project's current configuration; this repo does
  not enable `cacheComponents`, so do not add the `use cache` directive without
  first enabling and validating that model:
  <https://nextjs.org/docs/app/api-reference/directives/use-cache>.
- Google ignores sitemap `priority` and `changefreq` and may stop trusting
  inaccurate `lastmod` values:
  <https://developers.google.com/search/blog/2023/06/sitemaps-lastmod-ping>.
- Google removed the sitelinks search box in November 2024, so the nonfunctional
  `SearchAction` schema has no current benefit:
  <https://developers.google.com/search/blog/2024/10/sitelinks-search-box>.
- Next.js documents on-demand `import()` for external client libraries, which
  Plan 013 uses to keep SQL formatting out of the initial bundle:
  <https://nextjs.org/docs/app/guides/lazy-loading>.
- The official SQL Formatter project documents supported dialects, stored
  procedure/custom-delimiter limitations, maintenance status, and MIT license:
  <https://github.com/sql-formatter-org/sql-formatter>.

## Findings considered and deliberately not scheduled

- **Replace all server state with React Query/TanStack Query:** rejected for
  now. Astraa has only a few remote resources; a small typed hook plus bounded
  cache is easier to own. Reconsider when mutations, pagination, or many shared
  resources appear.
- **Rewrite the hash generator because it imports Node `crypto`:** not urgent.
  The audited browser interaction generated the correct MD5 result and the
  production build passed. A later standards-only cleanup may move it to Web
  Crypto, but it is not a confirmed defect.
- **Split components based only on line count:** rejected. Extract a component
  or hook only when it isolates state, a side effect, or independently testable
  logic.
- **Delete every unused `components/ui` primitive automatically:** rejected.
  Some may be intentional design-system inventory. Plan 005 requires a reviewed
  dead-code report and explicit allowlist.
- **Add generic SEO paragraphs to every page:** rejected. Plan 007 adds useful,
  intent-specific guidance and prioritizes pages with real search demand rather
  than word-count padding.
- **Enforce a strict Content Security Policy immediately:** deferred. Start with
  deployed-header inspection and CSP Report-Only after Sentry and third-party
  request paths are settled; enforce only when reports are clean.
- **Implement every planned tool/game in one pass:** rejected. The current
  prototypes do not share a launch-quality foundation. SQL has a bounded utility
  contract; Memory is the controlled first-game pilot; every other entry remains
  fail-closed until a separate demand/spec review.
- **Keep broken prototypes alive through Knip entry exemptions:** rejected.
  Public WIP routes can remain without preserving unsafe unmounted code. Plan
  013 deletes Music/Dino/Snake candidates and Plan 014 replaces Memory.
- **Copy the Astraa skills into `.agents` and `.claude`:** rejected because two
  canonical copies drift. Plan 008 tracks `.agents/skills/astraa-*` once and
  gives Claude resolving symlinks plus a drift gate.
- **Make Notion the technical docs renderer or iframe it:** rejected. The
  repository already owns reviewed architecture Markdown. Plan 011 renders it
  statically; Notion remains the direct Roadmap, Changelog, and Hall of Fame.
- **Use a large animated hero/canvas to make the landing page feel premium:**
  rejected. Plan 012 uses a fixed semantic SVG with restrained transform/opacity
  motion, complete reduced-motion fallback, and strict mobile performance gates.
