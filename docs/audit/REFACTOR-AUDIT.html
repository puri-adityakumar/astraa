Verdict consolidate & enforce, don't redesign

Structurally the codebase is on solid footing: the app→server-page→client-component→lib pattern is real and mostly honored, most lib modules ship unit tests, the strict-TS config is genuinely strong, and the core designs (error-handler funnel, lib/clipboard, the Zustand storage concurrency-lock, the off-thread regex/ReDoS worker, Next.js route error boundaries) are well-built. The dominant drag on maintainability is accumulated dead weight — roughly 5,000+ LOC of unreferenced UI primitives, an orphaned animation showcase and its transitive dependents, an abandoned Zustand-migration subtree, dead CSS, and 19 orphaned npm deps — compounded by systemic copy-paste of browser-IO helpers (blob-download, FileReader-to-Promise, clipboard, formatBytes) that no shared util captures. Good utilities exist but are under-adopted, and the total absence of a formatter/lint baseline lets style and convention drift rot unchecked. The correct posture is consolidation and enforcement, not redesign: delete the dead code, add tooling, extract the shared helpers, then adopt the funnels that already exist.
