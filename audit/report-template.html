Executive summary

The base grid is solid; two systematic bugs break it in daily use. The shared content column (sidebar → main → prompt) is geometrically consistent when the page is static — every surface measured at exactly 464↔1232. But (1) opened panels never snap to the top of the view — the scroll lands anywhere from 84px to 671px short, varying with history length and cache state — and (2) the moment the scrollback becomes scrollable, a space-taking scrollbar shifts the whole column 7.5px out of line with the prompt bar. On top of those, the terminal's signature element — the /command chip — has no fixed width, so every list (sidebar, home, help) has a ragged left edge where the reference site (claude.dev/terminal) snaps keys to one grid line.

P0 1 · Opened panels don't align to the top of the view

What happens

Running any panel command (/calculator, /json, …) echoes the command and opens the panel below the scrollback. The shell intends to scroll the panel header to the top of the column (scroll policy: panelChanged → "panel" → scrollIntoView(block:"start")). In practice the panel header lands at a different offset on every open — sometimes far below the fold, so the user sees only scrollback and believes the panel didn't open.

The pattern: the offset grows with the amount of scrollback history and shrinks with panel height — the signature of a scroll clamp, not a random race.

Root cause (instrumented & confirmed)

A wrapped Element.prototype.scrollIntoView log proved the shell does call scrollIntoView({block:"start"}) on the right [data-term-panel] section at the right time — but the scroll doesn't reach the top because:

  • Short panels can't be top-aligned at all. The scroll container can never scroll past scrollHeight − clientHeight. When the panel (plus its trailing padding) is shorter than the viewport, there isn't enough content below the panel top to push it to the top — the scroll clamps, leaving exactly viewport − panelHeight − padding px of drift. This alone explains the 84–264px warm numbers.
  • The dynamic-import race makes it worse on cold opens. The scroll computes against the short PanelLoading placeholder (128px). When the real client chunk finishes loading ~1s later and the panel grows, nothing re-scrolls. The 671px cold measurement is the loading-placeholder clamp exactly: 844 − 128 − 32(pb-8) ± growth ≈ 671.

Suggested fix

Two-part fix in components/terminal/panel-frame.tsx + the shell's scroll effect:

  1. Guarantee enough content below the panel so top-alignment is always possible — give the panel column a viewport-filling min-height: 
    // panel-frame.tsx — the TERM_COLUMN wrapper
<div className={cn(TERM_COLUMN, "pb-8", "min-h-[calc(100dvh-9rem)]")}>
    (9rem ≈ prompt bar + header allowance; tune once). Short panels like the markdown empty-state then fill the viewport and can be scrolled flush to the top — the leftover space lives inside the panel area instead of stranding the header.
  2. Keep the alignment while the panel settles instead of one-shot scrollIntoView — set the scroll position directly and re-apply while the panel grows (covers the dynamic-chunk swap): 
    // terminal-shell.tsx — "panel" branch of the scroll effect
if (action === "panel") {
  const el = main.querySelector<HTMLElement>("[data-term-panel]");
  if (el) {
    const align = () => { main.scrollTop = el.offsetTop; };
    align();
    const ro = new ResizeObserver(align);
    ro.observe(el);
    setTimeout(() => ro.disconnect(), 1500); // settle window
  }
}
    (main.scrollTop = el.offsetTop after fix-part 1 is equivalent to the clamped scrollIntoView but explicit; the ResizeObserver covers the PanelLoading → real client swap. Alternatively pass an onLoaded callback up from the dynamic import.)

P1 2 · Scrollbar shifts the column 7.5px out of line with the prompt bar

What happens

The scrollback/panel column lives inside <main> (the scroll container); the prompt bar lives outside it. When content becomes scrollable, main gets a classic 15px space-taking scrollbar (scrollbar-gutter: auto), its client width shrinks, and the centered column re-centers — 7.5px to the left of the prompt bar. The guest@astraa > gutter no longer lines up with the echoed commands above it — the terminal's most basic vertical line is broken on every screen that has any history.

Measured evidence

SurfaceColumn box (left→right)Content left (px-6)
Prompt bar column (outside main, no scrollbar)464 → 1232488.0
Scrollback/panel column (inside main, scrollbar present)456.5 → 1224.5480.5
Misalignment7.5px

main.offsetWidth 1184 − clientWidth 1169 = 15px scrollbar; computed scrollbar-gutter: auto. On static screens (no scroll) both columns measure exactly 464→1232 — proving the scrollbar is the only variable.

Fix (one line) in app/terminal/terminal.css:

/* Reserve the scrollbar gutter before scrolling starts so the column
   never shifts when history appears. */
[data-flavour="terminal"] main {
  scrollbar-gutter: stable;
}

Recommended companion: theme the scrollbars to the terminal aesthetic — the bright default scrollbar strip is clearly visible against the dark scheme in most screenshots:

[data-flavour="terminal"] main,
[data-flavour="terminal"] aside nav {
  scrollbar-width: thin;
  scrollbar-color: var(--term-surface2) transparent;
}

Apply the same scrollbar-gutter: stable to the sidebar's tool nav so its rows can't shift either. After this, re-run the measurement: prompt and scrollback content edges must both read 488.0 at 1440px.

P1 3 · Ragged key-chip columns — no shared grid line

What happens

The terminal's signature element is the /command chip. In every list — sidebar, home rows, prompt suggestions, /help — the chip sizes to its text, so the label next to it starts at a different x on every row. Scanning the tool list, the eye has no vertical line to follow.

Suggested fix

Fix in components/terminal/tool-row.tsx and the suggestion rows in prompt-bar.tsx — fixed-width key column:

<span className="w-24 shrink-0 rounded border border-term-surface2 px-1.5 py-0.5
              text-center font-mono text-xs text-term-accent">
  {`/${command.name}`}
</span>

w-24 (6rem) fits the longest chip (/snippet-generator truncates in the sidebar already; pick the width from the longest sidebar key, e.g. /calculator, /password). For /help, replace the per-block grid-cols-[minmax(0,auto)_minmax(0,1fr)] in components/terminal/output-blocks.tsx with one shared template so all categories align to the same value column:

className="grid grid-cols-[10rem_minmax(0,1fr)] gap-x-4 gap-y-1 ..."

P2 4 · Panel toolbar placement is inconsistent

JSON editor puts its view switcher (Text/Tree/Convert/Generate) at the top-left; the Snippet panel puts its equivalent switcher (Code/Screenshot) at the top-right next to Export; Base64 centers its Encode/Decode toggle; Calculator starts RAD/DEG at the left. Four panels, three different navigation placements.

Fix: adopt one rule and apply it everywhere — view/navigation switchers left, primary actions right. Concretely: move Snippet's Code/Screenshot segment to the left of its toolbar row; keep Export right. Calculator and Base64 already comply (they have no right-side actions).

P2 5 · Calculator: stray divider after RAD/DEG

A thin vertical divider floats a few px right of the DEG toggle, followed by a large empty gap before the right-aligned Ans = 0 — visible on desktop (x≈634) and mobile (x≈163). It reads as a misplaced separator rather than a deliberate one.

Fix: in components/calculator/calculator-client.tsx, either drop the divider or make the row a deliberate 3-part flex: [RAD/DEG] · flex-1 spacer · [Ans = n] with the divider given explicit height and margins (h-5 self-center mx-3 w-px bg-term-surface2) so it reads as intentional.

P2 6 · Markdown dropzone width breaks the panel grid

Every tool panel's card spans the full column content width (measured 480.5→1200.5 on the JSON panel). The Markdown empty-state dropzone is a narrower centered box (≈626→1070), leaving asymmetric-looking dead space at the panel's sides.

Fix: either stretch the dropzone to the panel width with inner padding (my recommendation — one grid everywhere), or make narrowness a documented pattern and apply it to all upload-style empty states (image resizer keeps its split layout, so full-width is the more consistent choice).

What's working well (keep these)

  • Base grid geometry is sound. Home, scrollback, panel and prompt columns all measure exactly 464→1232 in a static state; prompt gutter ↔ echo gutter line up; no horizontal overflow anywhere (scrollWidth == clientWidth on every screen tested).
  • Keyboard model is genuinely good. Enter submits, Tab completes, Esc dismisses suggestions and closes panels (verified live, incl. Radix-overlay awareness), Ctrl+L clears, ↑↓ recall — all confirmed working in the session.
  • Suggestion dropdown spans and aligns to the exact column; rows are 44px touch targets with chip + summary.
  • Command semantics are consistent — inline answers vs panel opens behave as documented; errors answer inline; bare commands open panels; the password stays masked with Reveal/Copy and a Sentry-masked element.
  • Themes switch cleanly — dracula and solarized-light verified live; light scheme text is readable; scheme survives in a cookie as designed.
  • Mobile adaptation is thoughtful — currency stacks its Fiat/Crypto toggle, the drawer + scrim behave, tool summaries hide on small screens, touch targets hold 44px.
  • The new browser panel works — sandboxed iframe loads example.com, address normalization adds https, back/forward stacks live in the shell, new-tab escape hatch present, iframe can't navigate the terminal (no allow-top-navigation).
  • /help output is well structured (categories, aliases, live/coming-soon markers, keyboard tips).

Benchmark: claude.dev/terminal (the inspiration)

The single biggest takeaway from the inspiration site: fixed key columns everywhere. Its sidebar keys, list dates, and row labels all sit on immutable grid lines — that discipline is exactly what finding #3 asks astraa to adopt, and it also implies the fix for the help listing (one shared value column). The prompt gutter sits precisely on the content column's left edge, which astraa already achieves — the scrollbar fix (#2) protects it.

What changed

  • One scroll region (P0 + P1 #2): the prompt bar is now sticky inside main — scrollback, panels and prompt share one width, so a scrollbar can never pull them apart (components/terminal/terminal-shell.tsx).
  • Panel top-alignment (P0): main.scrollTop is set directly and re-applied by a ResizeObserver while the panel settles (covers the dynamic-chunk swap), and the panel column carries min-h-dvh so short panels can always reach the top (panel-frame.tsx, terminal-shell.tsx).
  • Quiet, stable scrollbar: scrollbar-gutter: stable plus thin themed scrollbars on main and the sidebar nav (terminal.css) — the column no longer shifts when history appears.
  • Fixed key columns (P1 #3): w-24 command chips in tool-row.tsx and prompt-bar.tsx; shared 10rem key column for kv blocks at sm+ in output-blocks.tsx — the claude.dev/terminal grid discipline.
  • Snippet toolbar (P2 #4): view switcher left, export right — matching JSON.
  • Calculator divider (P2 #5): deliberate height/spacing instead of a stray mark.
  • Markdown dropzone (P2 #6): spans the column like every other panel card.
